24001010528 滕菲：JavaScript 的两种定时器

浏览器只提供两种定时器：setTimeout 到点执行一次，setInterval 每隔一段时间反复执行。 两者都返回一个数字编号（定时器 id），分别用 clearTimeout(id)、clearInterval(id) 取消。 时间单位都是毫秒，1000 毫秒 = 1 秒。

一、setTimeout：延迟执行一次

点「开始」后，下面的提示先倒数 3 秒，然后由 setTimeout 的回调把结果改掉；点「取消」验证 clearTimeout 的效果。

DEMO 01 / setTimeout
还没开始。点「开始」后等 3 秒。
// setTimeout(要执行的函数, 毫秒)
var id = setTimeout(function () {
    out.textContent = "3 秒到了，这个回调只执行这一次";
}, 3000);

// 还没执行之前，可以取消：id 就是 setTimeout 的返回值
clearTimeout(id);

二、setInterval：隔一段时间执行一次

每 100 毫秒给数字加 1，所以看起来像秒表。点「暂停」要调用 clearInterval，否则它会一直跑下去。

DEMO 02 / setInterval
0.0秒（每 100 毫秒更新一次）
setInterval 还没启动。
// 每 100 毫秒执行一次，直到被 clearInterval 停掉
var timer = setInterval(function () {
    tenths++;
    clock.textContent = (tenths / 10).toFixed(1);
}, 100);

clearInterval(timer);   // 暂停 / 停止

三、两种定时器对比

对比项 setTimeout setInterval
执行几次 只执行一次 每隔一段时间执行，无限次
怎么取消 clearTimeout(id) clearInterval(id)
返回值 数字 id 数字 id
常见用途 延迟提示、防抖、延迟跳转、递归轮询 时钟、轮播图、进度条、定时刷新
停不下来的后果 顶多多执行一次 页面一直占用 CPU，回调越积越多

四、执行顺序：setTimeout(fn, 0) 也不是马上执行

定时器的回调必须等主线程的空闲时间，所以写在后面的同步代码反而先执行。点按钮看真实顺序。

DEMO 03 / 事件循环
点「运行一次」看四行输出的顺序。
out.push("① 同步代码 A");

setTimeout(function () {
    out.push("④ setTimeout(…, 0) 的回调");   // 排队，等同步代码跑完
}, 0);

out.push("② 同步代码 B");
out.push("③ 同步代码 C");

五、写的时候要注意的四件事

1. 单位是毫秒。要 3 秒就写 3000，写 3 是 3 毫秒，肉眼几乎看不出来。

2. 时间不精确。定时器只保证"至少等这么久"，主线程忙（比如在跑一个大循环）时回调会被推迟。

3. setInterval 会累积误差。每次执行耗时不同，间隔就会慢慢漂移；需要稳定节奏时用"递归 setTimeout"： setTimeout(step, 1000) 写在 step 里面，每次都重新计时。

4. 记得停止。页面切换、组件销毁时要 clear；后台标签页里浏览器会把定时器节流到约 1 秒一次，别拿它做精确计时。
