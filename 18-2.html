24001010528 滕菲：电商全站系统架构图（canvas 绘制）

这张图不用图片、不用 SVG，全部由 canvas 2D 的路径画出来：圆角矩形当模块、虚线的层框当分层、 三角箭头表示调用方向。整张图先在一个 1180 × 950 的虚拟坐标系里排好， 再按画布实际宽度整体缩放，所以换屏幕尺寸排版不会乱。鼠标悬停任意模块会高亮并显示它的职责。

分层各自负责什么

接入层：把请求挡住、分出去 浏览器到 Nginx 之前先过 CDN，静态资源就近返回；动态请求再交给 API 网关统一鉴权、限流和路由， 应用层就不必各自处理登录态。
应用层：按业务拆服务 商品、订单、支付、库存各自独立部署，之间用 RPC 或消息队列通信。 下单要先预占库存，支付回调再扣减，所以订单与库存是通过消息最终一致的。
支撑层与数据层：快慢分开 热点数据放 Redis 挡住读流量，写请求落 MySQL 主从； Elasticsearch 负责搜索与日志，数据仓库只跑离线报表，不和线上抢资源。
